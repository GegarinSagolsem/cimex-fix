# AGENTS.md

Guidance for coding agents (IBM Bob, Claude Code) working in this repository. The first version of this file was
generated by IBM Bob's `/init`.

## Rules
- Every number shown in the UI, the README or the submission must come from `docs/benchmark.md` (generated by
  `scripts/build-benchmark.mjs`) or a source listed in `docs/sources.md`.
- Never commit secrets: `.env*` stays in `.gitignore` and `.bobignore`; document variable names in `.env.example`.
- Bob-native parts (custom modes, per-mode rules, skills, MCP config) live in `bob/pack/` and are built and run in IBM Bob.
- `docs/answer-key/` is excluded from Bob by `.bobignore`; never show it to a run.

## Monorepo structure
```
apps/web          → Mission Control: Next.js 16 (App Router, TypeScript, Tailwind v4)
packages/shared   → @bugproof/shared: zod schemas shared by the web app and the MCP server (ESM, builds to dist/)
packages/mcp      → the Cimex Fix MCP server: open_case, record, evidence, run_tests, bisect, publish_proof
bob/pack/         → the Bob pack: 4 custom modes, per-mode rules, 3 skills, mcp.json
scripts/          → benchmark generation, the one-shot model baseline, the Bob pack installer
docs/             → benchmark, sources, answer key, raw model-baseline answers
```

## Commands
```bash
# From the repo root:
npm run dev                                         # Mission Control on http://localhost:3000
npm run build                                       # builds packages/shared, then apps/web
npm run typecheck                                   # tsc --noEmit in every workspace
npm run build -w bugproof-mcp                       # builds packages/mcp/dist/index.js (esbuild)
node scripts/install-bob-pack.mjs <target repo>     # copies the Bob pack into <target repo>/.bob/
node scripts/export-cases.mjs && node scripts/build-benchmark.mjs   # regenerates docs/benchmark.md

# From apps/web/:
npm run lint                                        # ESLint (next/core-web-vitals + typescript)
```

## Non-obvious patterns
- **`@bugproof/shared` must be built before `apps/web`**: it resolves to `dist/index.js`. The web app's `pre*`
  scripts build it; after changing a schema, rebuild it before relying on a running dev server.
- **Zod types are dual-declared**: every schema is both a zod validator and a type with the same name
  (`export const Case = z.object(...)` + `export type Case = z.infer<typeof Case>`). Follow this in `packages/shared/`.
- **`packages/shared` is ESM** (`"type": "module"`): import paths inside it use the `.js` extension.
- **Tailwind v4 tokens** are CSS custom properties in `apps/web/src/app/globals.css`, exposed via `@theme inline`.
  The light "sky & lime" theme is the default; dark comes from the toggle. Use `bg-[var(--bg)]`,
  `text-[var(--accent)]` and the `--*-ink` tokens for text on tinted chips, not raw Tailwind colour names.
- **Windows paths in the MCP server**: a lowercase drive letter (`c:\…`) makes Vitest load twice and every test
  error, so `resolveRepoPath` upper-cases it. Keep that when touching path handling.
- **Test lock**: `run_tests` with `expect: "red"` hashes every file under `tests/` plus the Vitest config into a lock
  in the OS temp folder (outside the repo); `publish_proof` refuses a `proven` status if any of them changed or
  disappeared since, or if no lock exists for the case.
- **The demo target repo is separate** (`bugproof-demo-shoplite`): `git bisect` needs its clean, linear history.
- **App pages scroll inside the shell**, not the window: the shell is `h-screen overflow-hidden` and its scroll
  areas are `relative`, so absolutely positioned children (e.g. `sr-only` labels) stay inside them.
